# Contributing

Thanks for helping improve OpenQCY Desktop.

1. Open an issue before adding support for a new device or protocol command.
2. Never submit firmware images, account tokens, private keys, device identifiers, or captures containing unrelated personal traffic.
3. Include the model, firmware version, app version, transport, service/characteristic UUIDs, request bytes, response bytes, and reproduction steps for protocol findings.
4. Keep protocol parsing separate from UI code and include deterministic tests.
5. Run the build and tests before opening a pull request.
